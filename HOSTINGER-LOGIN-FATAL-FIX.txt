SIMAMIA FLOAT - HOSTINGER LOGIN_FATAL_ERROR FIX
================================================

This package fixes the deployed login failure that returned:
"Login could not be completed. Check Hostinger Runtime logs for LOGIN_FATAL_ERROR."

Corrections included
--------------------
1. Prisma versions are pinned together at 7.8.0:
   - @prisma/client 7.8.0
   - @prisma/adapter-mariadb 7.8.0
   - prisma 7.8.0
   This avoids a Prisma Client / driver-adapter runtime mismatch.

2. Login reads only core User columns required for authentication.
   Older imported databases therefore do not fail login just because newer
   optional profile columns are absent.

3. scripts/ensure-hostinger-schema.mjs runs before Next.js starts.
   It adds only missing compatibility columns and extends CompanyStatus with
   DISABLED. It does not delete existing rows.

4. Database errors now inspect nested Prisma/MariaDB driver errors and return
   a useful safe error category rather than always LOGIN_FATAL_ERROR.

5. /broker/dashboard and /gps-manager/dashboard now exist, so those roles do
   not authenticate successfully and then land on a 404.

6. The stale app/agent-location/%5Btoken%5D route was removed.

7. Company Admin collection routes were repaired:
   - POST /api/company-admin/gps-devices now creates a GPS device/token.
   - GET  /api/company-admin/gps-devices lists devices.
   - POST /api/company-admin/bank-verifications creates a record.
   - GET  /api/company-admin/bank-verifications lists records.
   Their [id] PATCH routes remain responsible for record updates.
