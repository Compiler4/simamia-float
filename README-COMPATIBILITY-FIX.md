# Simamia Live Location Service v1.1 — Prisma Compatibility Fix

This package resolves the runtime error:

```text
Unknown field `locationSource` for select statement on model `BrokerCustomer`.
```

## Why the error happened

The live-location code selected `BrokerCustomer.locationSource` and
`BrokerCustomer.locationVerifiedAt`, but the Prisma Client currently generated
in the project does not contain those fields. Prisma validates every selected
field before running the SQL query, so the complete endpoint failed before it
could return map data.

## What this version changes

- Removes unsupported Prisma `select` fields from the broker query.
- Derives a display-only location source from existing columns:
  - `STAFF_GPS` when `attendedDate` exists.
  - `IMPORTED` for imported agents.
  - `DATABASE` for other saved coordinates.
  - `UNMAPPED` when latitude/longitude are absent.
- Uses `attendedDate` or `updatedAt` as the location timestamp.
- Saves real broker latitude/longitude without requiring new metadata columns.
- Keeps service visits, service activities, assignment checks, notifications,
  map pointers, and GPS history working.
- Makes the React location metadata types optional.

## Commands

```powershell
Ctrl + C
npx prisma format
npx prisma validate
npx prisma db push
npx prisma generate
if (Test-Path ".next") { Remove-Item -Recurse -Force ".next" }
npm run dev
```

## Important

Do not edit `.next/dev/server/chunks/*`. Those files are generated by Next.js.
Always edit the source files under `app/`, `lib/`, and `prisma/`, then delete
`.next` and restart.

## Expected endpoint

After signing in as Staff, open:

```text
http://localhost:3000/api/staff/live-locations
```

It should return JSON containing `success: true`, `points`,
`registeredAgents`, `customers`, and `visits`.
